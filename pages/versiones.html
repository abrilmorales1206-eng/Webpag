Control de versiones

En esta página:DefiniciónTipos de sistemasFuncionamiento y gestión de cambios

Definición

Es un sistema que registra los cambios hechos a los archivos de un proyecto a lo largo del tiempo. Permite volver a versiones anteriores, saber quién cambió qué y trabajar en equipo sin pisar el trabajo de otros.

Tipos de sistemas

Local

Las versiones se guardan en el mismo equipo (ejemplo: RCS).

Características: simple, sin servidor.

Ventajas: fácil de usar y rápido.

Desventajas: sin colaboración y un fallo del disco pierde todo.

Centralizado

Un servidor guarda el historial y cada persona trabaja contra él (ejemplos: SVN, CVS).

Características: un único repositorio central.

Ventajas: control claro de accesos y fácil de entender.

Desventajas: si el servidor falla no se puede versionar; requiere conexión.

Distribuido

Cada persona tiene una copia completa del historial (ejemplos: Git, Mercurial).

Características: ramas baratas, trabajo sin conexión.

Ventajas: rápido, resistente a fallos y flexible.

Desventajas: curva de aprendizaje mayor y puede haber conflictos al fusionar.

Funcionamiento y gestión de cambios

El flujo básico es: modificar archivos, seleccionarlos (stage) y guardarlos con un commit que lleva autor, fecha y mensaje. Las ramas permiten desarrollar funciones por separado y luego unirlas con merge. El historial (log) y las diferencias (diff) permiten rastrear cada cambio; las etiquetas marcan versiones publicadas.

git init
git add .
git commit -m "Primera versión de la app"
git branch login
git switch login
git merge main
git log --oneline
git diff
